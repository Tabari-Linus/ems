## 1. Frontend ↔ backend integration — broken today

These are concrete contract mismatches; each one makes a feature fail at runtime.

| # | Feature | Problem | Evidence |
|---|---|---|---|
| I1 | **Session survives reload** | Access token is held in memory only; nothing tries a silent refresh on app start, so a page refresh → `authGuard` sees no token → `/login`. And even if it tried: the refresh cookie is set with `Path=/auth` but the endpoints are `/api/v1/auth/*`, so the browser **never sends the cookie**. Refresh + server-side logout cannot work. | `token.service.ts`, `app.config.ts`; `AuthController.java:19,65,75` [V] |

Even with that removed, the backend binds `@Argument Long companyId` while the schema arg is `id` → always `null`. **update/archive/delete company can never succeed.** | `companies.ts:69-75`; `CompanyController.java:36,46,65` [V] |

## 2. Frontend — best-practice issues

**Architecture**
- Hand-written GraphQL strings + hand-written TS interfaces that have already drifted from the schema (I2–I6 are all symptoms). No codegen, no typed documents, no schema validation at build time.
- No consistent data-access pattern: services return `Observable`, every component immediately wraps in `firstValueFrom`, then uses a mix of `resource()`, manual `signal` + `.then()` (staff), and `async` methods. No `rxResource`/`httpResource`, no cache, no request cancellation (staff search uses `setTimeout` debounce with no cancellation of in-flight requests).
- Models live in `settings.models.ts` (generic `PageResult`, `ApiResponse` there); some input interfaces live inside services. No feature-level folder structure (components, data-access, models per feature).
- Large, multi-responsibility components: `my-profile` (322 TS / 401 HTML / 493 SCSS), `profile` (3 copy-pasted "edit X" blocks of 4 signals each), `staff` (list + add-modal + dropdown loading).
- Duplicated helpers: `getInitials` / `getAvatarColor` ×3 with **two different palettes**, `formatDate`, status chips, inline SVG icons repeated across templates.
- No shared UI layer (button, modal, table, form-field, status-chip, empty/loading/error states, confirm dialog). Archive/deactivate have no confirmation.
- Settings tabs are not routes (no deep link / back button), no search/filter/pagination in tables.
- Single `environment.ts` with hard-coded `http://localhost:8080`; no prod environment / `fileReplacements`, no dev proxy.

**Auth**
- JWT decoded client-side for permissions and expiry; no `me`/session bootstrap; no proactive refresh before expiry; `logout()` navigates before server call; `authGuard` only checks in-memory expiry.

**Quality / a11y / misc**
- Only test is `app.spec.ts`, and it's broken (asserts `<h1>Hello, ems-frontend</h1>`).
- `index.html` has two `<title>`s ("EmsFrontend" and "PeopleOS").
- `unauthorized.ts` uses an old purple palette (`#667eea`) and `staff.ts` an old avatar palette, inconsistent with the PeopleOS tokens in `styles.scss`.
- Settings form `<label>`s aren't associated with inputs; dropdown menus are click-only divs; `@HostListener` instead of `host` metadata.
- No lint (ESLint/angular-eslint) configured; Prettier present but no script.
- `design_system.pdf` exists — not yet checked against the implementation.

## 3. Backend — issues (summary; full detail available)

**Critical/High security**
- C1 refresh cookie path (see I1).
- C2 privilege escalation: `MANAGE_EMPLOYEE` can set any employee's `accessLevelId` (incl. their own → ADMINISTRATOR) without `MANAGE_ACCESS_LEVEL`.
- Archived/deleted employees keep login + refresh (UserAccount never disabled); archived/deleted access levels still grant permissions.
- Access token lifetime 8h, unrevocable; permissions changes apply only at next refresh.
- No password lifecycle: temp password emailed in plain text, no change/reset endpoint, no lockout/rate-limit, login email case-sensitive, changing `workEmail` doesn't update login email.
- Refresh tokens stored plaintext, one session per user (login on device B logs out A), no reuse detection.
- Minimal JWT validation (no issuer/audience check); introspection on in all profiles; no query depth/complexity limits; TRACE bind logging of PII in dev.

**API design**
- Mixed mutation result types (`ApiResponseX` vs `ActionResult`), mixed activate semantics (`activateX(id, active)` vs `activateX`+`archiveX`), mixed filters, `getCompanies(SortInput:)` capitalised arg + controller reads `filter` that doesn't exist.
- Schema ↔ Java DTO drift (company list `companyStatus`/`nextOfficeNumber` always null, `companyPhone` + `companyPhoneNumber` duplicates, Java `@NotBlank` on schema-optional fields).
- Inconsistent error codes (not-found is `INPUT_VALIDATION_ERROR` in company/office/dept, `NOT_FOUND` elsewhere; access denied reported as `UNAUTHENTICATED/FORBIDDEN`; bad sort field → INTERNAL_ERROR).
- Dates typed as `String` (dateOfBirth, dateHired, dashboard period); `isExpert` is a String; `dateHired` is never persisted; `scalar Date` registered but unused.
- No `me` query returning permissions/account info.
- Employee's `department.office` always null → UI can't show office/company.
- Admins can't manage another employee's addresses/IDs.
- N+1 in `getCompany` and `getAccessLevel`; unbounded nested lists including soft-deleted children.

**Code / data**
- Soft delete not honoured in company/office/department lists and lookups; employees can be assigned to deleted/archived entities.
- Module structure inconsistent (XUtil vs XValidator, PersistenceHelper only in some modules, `common/Pagination` capitalised); dead code (`DepartmentInput`, `CreatePermissionInput`, `CompanyPageResult`, unused inputs); CLAUDE.md mentions MapStruct but it's not used.
- Self-service has no `@Transactional`; bio/contact updates are full replacement (null wipes data); `LocalDateTime.now()` labelled as UTC.
- Department names unique system-wide (can't have "HR" in two offices); no FK indexes; company table has no NOT NULL/UNIQUE; `out-of-order`/`baseline-on-migrate` on in base profile; test migrations are a hand-copied fork.
- Tests: Office & Department have none; Company almost none; no `GraphQlTester` schema-mapping tests (which is why I3/G1 slipped); no Testcontainers; no JaCoCo despite 85% target.
- Config: non-dev profiles fail to start (jwt/admin/cors only in dev yaml); `SPRING_PROFILES_ACTIVE` defaults to dev; `.env.example` incomplete/misnamed; CORS only allows GET/POST/OPTIONS + 2 headers.
